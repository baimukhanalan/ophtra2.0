# Desktop jitter: Chrome (channel `chrome`), 1440×900 / 1280×720 / 1920×1080

Production site: https://ophtra2.vercel.app. Tested 2026-09-28.

**Coverage**
- 1440×900: all 88 ru sitemap routes.
- 1280×720 and 1920×1080: a 24-route subset (every page type, plus every page with StackCards, StickyStory or HorizontalScroll).
- Separate probes for pin edges, the mega-menu, magnetic buttons, hover layout shift, the custom cursor and sticky sub-bars versus header hide.

**How it was driven**
- Each route runs through repeated cycles until the page bottom is reached:
  - slow: 12 × 100 px wheel ticks, 110 ms apart
  - fast: 10 × 100 px, 16 ms apart
  - trackpad: 70 × 8–30 px deltas, 16 ms apart
  - fast up: 8 × −100 px
  - trackpad up: 30 × −(8–30) px, every second cycle
- After every burst the page is left idle for 1.5 s to watch the settle.
- A 100 px tick is animated in the page (150 ms ease-out) to mimic Chrome's smooth wheel. Scrolling is driven inside the page because the machine was heavily loaded: CDP wheel latency reached about 150 ms per event.
- A requestAnimationFrame (rAF) recorder logs every fixed, sticky, transformed, parallax, magnetic and inline-CSS-variable element each frame. It also records layout shifts, header `data-hidden` changes and changes to `html[data-*]`.

Scripts and raw data are in `audit/jitter/_work/desktop-jitter/`: `sweep.cjs`, `recorder.js`, `pins.cjs`, `stk2.cjs`, `menu3.cjs`, `interact.cjs`, `cursor.cjs`, and `r1440a.json` / `r1440b.json` / `r1280.json` / `r1920.json` / `pins*.jsonl`.

## Checked and clean (no reproducible jitter)

- **Header hide/show:** no flapping. Each downward burst gives exactly one hide and each upward burst one show at 1440, 1280 and 1920 (trackpad deltas of 8–30 px included). An earlier run showed flapping, but it came from a bug in my own driver: the eased scroll went negative. The 6 px hysteresis in `Header.tsx:72` holds.
- **Floating launchers and `html[data-past-hero|over-cta|over-footer]`:** each flag flips once per crossing; no toggling at thresholds.
- **StickyStory visual (`.oph-story__sticky`):** holds its pin top to within 0.6 px on all 6 routes, with no jump at pin start or end. Only the chapter index changes.
- **Magnetic buttons:** a pointer parked at the edge with 1–3 px wiggles gives no oscillation. The button is still (1 distinct position) once the pointer stops.
- **Mega-menu across groups:** moving label to label keeps the panel open; content swaps without a fade (panel height 448/451 px). The only failure is D3.
- **Hover sweep:** 100+ links, cards and buttons per route on 6 routes. No layout shift from hover apart from a 0.00008 text shift on `a.oph-herolink`.
- **Images:** every `<img>` has `width` and `height` (`components/Photo.tsx`, knowledge video poster). No image-load shifts were recorded.
- **Page layout during scroll:** apart from D6 and D8, no layout shift over 0.0005 on any of the 88 routes.

## Code-only suspicions (not reproduced as visible jitter)

- `.oph-pagehero__inner` (`shell.css:453`, `--p` × −70 px, lagged). The recorder logged 1–3.7 px back-and-forth during slow wheel scrolling on 21 routes. This is most likely a rAF-ordering artifact of the synthetic driver (the engine may read scrollY before the driver's `scrollTo` in the same frame). Real wheel input scrolls before rAF, so I don't count it. It is still text on a lagged transform; see D5.
- `oph-home-founder__swirl` sets `transform: rotate(var(--oph-scroll-progress))` at `home.css:544`, which is overridden by `transform: none` plus a 60 s spin at `home.css:643`. That is dead code, not jitter.
- `PremiumCursor` in `components.tsx:225-231` runs a permanent rAF loop and uses a per-frame factor of 0.22, so it moves twice as fast at 120 Hz. No visible idle writes were measured.
- The machine was heavily loaded (load average 50–100 from parallel agents). Durations were measured at 60 fps (a few retried routes ran at 32 fps). Amplitudes don't depend on frame rate.
